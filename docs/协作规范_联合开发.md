## 1. 第一步：把仓库推上远端（今天就能做）

### 1.1 建仓

GitHub 或 Gitee 都行。**建议建私有仓库** —— `assets/CREDITS.md` 里记录了素材来源，
其中带 `{IS}` 标记的是任天堂素材（原型可用、不可发布），公开仓库会带来授权争议。

### 1.2 推送

```bash
# 分支改名为 main（惯例）
git branch -M main

# 加远端（换成你自己的地址）
git remote add origin git@github.com:<你的账号>/infinite-loop.git

# 国内网络需要走代理（否则推不上去）
git config http.proxy http://127.0.0.1:7890
git config https.proxy http://127.0.0.1:7890

# 首次推送（LFS 会自动处理大文件）
git lfs install
git push -u origin main
```

### 1.3 让队友能克隆

**克隆方必须先装 git-lfs**，否则拿到的是指针文件而不是真图：

```bash
git lfs install          # 只需一次
git clone <仓库地址>
cd infinite_loop
godot --headless --path . --editor --quit   # 注册 class_name，必须做
```

## 2. 分支与保护

| 分支 | 用途 | 谁能推 |
|---|---|---|
| `main` | 随时可玩、测试全绿 | **设保护，只能通过 PR 合入** |
| `feat/xxx` | 新功能 | 各自 |
| `fix/xxx` | 修 bug | 各自 |
| `art/xxx` | 美术 | 美术 |
| `docs/xxx` | 文档 | 各自 |

GitHub 上把 `main` 设为 **Protected Branch**，勾选：
- Require pull request before merging
- Require status checks to pass（配合第 5 节的 CI）

**这样"改坏了"在合并前就会被拦住，而不是等对方 pull 下来才发现。**

## 3. 测试就是我们的协作契约

项目已有 **26 项自动化测试**（单测 10 + 场景 16）。这不是"锦上添花"，**它是协作的核心机制**：

> 你不需要知道队友改了什么。**只要测试还是绿的，就说明他没破坏你依赖的东西。**

因此纪律是：

1. **动任何逻辑前先跑一遍全量测试**（确认基线是绿的）
2. **改完再跑一遍**（确认自己没破坏别的）
3. **新增功能必须带测试**
4. **测试红了不许合并**

```bash
# 单测（无 autoload，用 -s）
for t in dice_test combat_test content_test world_test bloodline_test \
         bloodline_combat_test bloodline_mitigation_test attr_redesign_test \
         los_test rooms_test; do
  godot --headless --path . -s res://tests/$t.gd
done

# 场景测试（有 autoload，必须 .tscn）
for t in flow_driver real_flow_test persist_test patrol_test flee_test \
         rooms_test item_heal_test scenario_entities_test; do
  godot --headless --path . res://tests/$t.tscn --quit-after 6000
done
```

## 4. 分工：按**目录**切，不要按"功能"切

这个项目的结构天然适合按目录分工 —— 两边几乎不碰同一个文件。

| 方向 | 写入范围 | 做的人 |
|---|---|---|
| **战斗系统** | `combat/`、`systems/combat*.gd` | A |
| **箱庭与探索** | `scenarios/r001_apartment/` | B |
| **UI** | `ui/` | A 或 B（看谁先动） |
| **美术资源** | `assets/`、`tools/pixelart/` | 美术 |
| **数值与内容** | `defs/`、`content.gd`、`dialogs.gd` | B |
| **测试** | `tests/` | 各人负责自己模块 |

### 三条硬约定（避免 Godot 特有的冲突）

1. **`project.godot` 只由一个人改**（autoload、输入映射、显示设置都在里面，最容易冲突）
2. **同一个 `.tscn` 场景文件，同一时间只有一个人改**（GDScript 能合并，场景文件基本不能）
3. **`assets/CREDITS.md` 谁加素材谁更新**，写清来源与授权

### 开工流程

```
1. 开 Issue：「我要做 XXX，会动 <目录>」
2. 队友看一眼，确认没人在动同一个文件
3. 开分支 → 改 → 跑测试 → 提 PR
4. 对方 review（哪怕只看一眼测试结果）
5. 合并，删分支
```

**第 1 步花 30 秒，能省掉几小时的冲突调解。**

## 5. CI：把测试变成自动闸门（强烈建议）

在 `.github/workflows/test.yml`：

```yaml
name: tests

on:
  push:
    branches: [main]
  pull_request:

jobs:
  godot-tests:
    runs-on: ubuntu-latest
    container:
      image: barichello/godot-ci:4.7.2
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true

      - name: 注册 class_name
        run: godot --headless --path . --editor --quit

      - name: 单元测试
        run: |
          for t in dice_test combat_test content_test world_test \
                   bloodline_test attr_redesign_test los_test rooms_test; do
            godot --headless --path . -s res://tests/$t.gd || exit 1
          done

      - name: 场景测试
        run: |
          for t in flow_driver real_flow_test persist_test patrol_test flee_test; do
            godot --headless --path . res://tests/$t.tscn --quit-after 6000 || exit 1
          done
```

加了之后，**任何 PR 测试不过就合不进去** —— 这是最省心的协作保障。

## 6. ⚠️ Godot 协作的四个大坑（新人必读）

### 坑 1：`-s xxx.gd` 模式没有 autoload
用 `-s` 跑脚本时 `Game` / `EventBus` / `DebugLog` 都不存在，会报 `Identifier not found`。
**要 autoload 就必须用 `.tscn` 场景模式跑。**

### 坑 2：新拉的仓库会报"找不到 xxx 类"
`class_name` 的注册信息在 `.godot/` 里，而它被 gitignore 了。
**首次拉取后必须执行一次**：
```bash
godot --headless --path . --editor --quit
```

### 坑 3：截图脚本不要加 `--headless`
加了会截出全黑图。GUI 脚本用：
```bash
godot --path . res://tests/shot_rooms.tscn
```

### 坑 4：美术素材授权
`assets/CREDITS.md` 里 `{IS}` = 任天堂素材（**原型可用、不可随成品发布**）；
`[F2E]` / `[F2U]` 可自由使用；`{author}` 需署名。
**加素材必须同时更新 CREDITS。**

## 7. 排查问题：先读日志，不要靠截图

游戏内置结构化操作日志 `DebugLog`（`autoload/debug_log.gd`）：

```gdscript
DebugLog.ev("battle", "战斗结束", {"victory": true, "hp": 16, "kills": 2})
DebugLog.count("battle")            # 某类事件次数
DebugLog.find("用药")                # 含关键词的行
DebugLog.dump("user://run.log")     # 落盘
```

**为什么强调这个**：本项目之前修 bug 全靠人工逐张看截图，结果**漏掉了一个极明显的 bug** ——
"连吃四个急救包，血反而越来越少"。直到加了结构化日志，才一行 `hp:[6,14]` 就看清了。

> **纪律**：只记录事实，不记录判断；数值一律带前后值。
