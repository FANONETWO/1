## 三、不可破坏的约定（改代码前务必看）

### ① 单一状态源：`Game.dungeon`
已击杀的敌人、已拾取的交互点、线索标记，**全部只在 `Game.dungeon` 里**，
通过 `Game.mark_killed()` / `is_killed()` / `mark_taken()` / `is_taken()` 读写。

> **不要**再引入第二处状态（本项目曾因此出过"尸体复活"的 bug）。
> 存档会带上 `dungeon`，所以关掉游戏再开，尸体也不会复活。

### ② uid 前缀：探索层用 `"房间/裸id"`
- 敌人：`"corridor_n/enemy_7_2"`
- 交互点：`"utility/seal_912"`
- NPC：`"duty_room/chen"`

**战斗单位的 uid 必须与探索层一致**（`CombatUnit.from_enemy(..., uid_override)`），
否则"已击杀"表里的 key 对不上，尸体会复活。
**`match` 之前记得剥前缀**（`e.get("def_id", nid)`）。

### ③ 箱庭出口契约：`exits[方向].cell` 是**本房间**的出口格
不是目标房间的落点。
落点由 `_entry_cell_from()` 在目标房间里**反查**（找"能回到来路"的那扇门）。
**门必须真的是地图上的 `D` 字符**，否则走不出去 —— `rooms_test.gd`（62 项断言）守着这条。

### ④ 血统装配要写 `picked`
```gdscript
c.bloodlines = [
    {"id": "infected", "rank": "B", "picked": ["claws", "proliferate"]},
    {"id": "werewolf", "rank": "B", "picked": ["steel_claw", "blood_moon"]},
]
```
只给 `rank` 不给 `picked` → `bloodline_nodes()` 返回空，**所有加成为 0**。
`rank` 只决定能选到哪一级。

### ⑤ 血量同步方向：战斗单位 → 角色卡
`BattleScene._apply_player_hp()` 必须是 `_player.hp = pu.hp`。
**写反了，吃药回的血会被旧值当场覆盖** —— 这个 bug 曾导致"连吃四个急救包血还在掉"。

## 四、已知坑清单（新人必踩）

### 敌人视野锥：三处曾经踩空的地方（改视野务必先看这条）

1. **换房间必须重算视野**：`_load_room()` 末尾要 `_sight_sig = "` + `_refresh_sight()`。
   漏了它，进屋后画面上一个视野格都没有 —— 潜行信息直接为零
2. **缓存签名要含 uid + 位置 + 朝向 + 格数**：只比 uid 的话，巡逻兵转身/移动后视野锥会冻结在旧位置
3. **锥形是 90°（±45°），判据 `|d·f| ≥ |d×f|`**：只写 `d·f > 0` 是 180°，侧后方也会被「看见」，
   与教程承诺的「背后 = 突袭」矛盾

另外两条渲染纪律：

- 视野分两层：亮红 `_attack` = 此刻会看见你；暗红 `_watch` = 其它敌人的视野（预警）
- **亮红必须画在迷雾之上**（否则玩家会在看不见的地方被发现）；暗红留在迷雾之下（保留恐怖感）


### ⚠️ 仓库首页 README 是**刻意留空**的（不要往里写内容）

- 作者明确要求：不对外展示、不吸引任何人 —— `README.md` 保持 **0 字节**
- **不要「修复」远端对它的清空提交**：那是有意为之，不是手滑（已经因此被覆盖过两次）
- 也不要往仓库 About 里填描述、不要加 topics
- 完整项目说明在 [`docs/项目说明.md`](项目说明.md)；首页空白不影响开发


| 坑 | 现象 | 解法 |
|---|---|---|
| **`-s` 模式没有 autoload** | 脚本里用 `Game` 报 `Identifier not found` | 改用 `.tscn` 场景模式跑 |
| **`-s` 里引用 autoload = 进程挂死** | 测试永远不退出、CPU 空转，而且 stdout 被缓冲，**连错误都看不到** | 逻辑层别直接写 `DebugLog.xxx`（编译期就炸）；改成"取不到就跳过"的安全访问 |
| **测试没有时间上限** | 一个 `await` 循环等不到条件 → 无限等 → 整批回归被拖死 | 每个测试 `_ready()` 第一行加 `TestGuard.arm("xxx_test", 45.0, get_tree())` |
| **玩家 AP 不恢复（打不动）** | 第一回合用完 6 点 AP 后再也攻击不了 | 轮到某单位时**必须**调 `_cm.begin_unit_turn(u)`，并 `_cm.set_current(u)` 同步当前单位 |
| **`class_name` 未注册** | 满屏 `Identifier not found` | 跑一次 `--headless --path . --editor --quit` |
| **截图全黑** | 图片是纯黑 | **不要加 `--headless`** |
| **隐藏按钮不能点** | 点了没反应 | `_find_btn` 必须检查 `is_visible_in_tree()` 与 `disabled` |
| **动态按钮坐标是旧值** | 点击落空 | 取 `get_global_rect()` 前先 `await RenderingServer.frame_post_draw` |
| **`is_walkable` 挡住交互** | 柜子/桌子点不响 | 交互检测要放在可行走检测**之前** |
| **结算文案 `%` 报错** | `String formatting error` | 字面量百分号写 `%%` |
| **`CanvasLayer` 面板关不掉** | 画面被永久遮挡 | 记引用 + 接 `closed` 信号释放 |
| **GDScript 语法** | `if not await f()` 报错 / `Vector2i` 没有 `.max()` | 先 `var ok := await f()`；用 `maxi(absi(...))` |

## 六、系统速查

### 属性（9 项，各有战棋出口）
`力量`（近战伤害）`敏捷`（移动/防御）`耐力`（生命上限 = 8+4×耐力）`智力`（战术点）
`感知`（暴击率 = 5%×感知）`决心`（意志池 = 2×决心）`风度`（指挥光环）
`操控`（威慑：敌人骰池 −1，≥4 时 −2）`沉着`（先攻 + 首击减伤）

### 战斗数值
- 玩家生命 = `8 + 4×耐力`；意志 = `2×决心`
- 移动力 = `3 + 敏捷/2`；战术点 = `智力/2`；光环半径 = `风度/2`
- 暴击率 = `5% × 感知`；首击减伤 = `沉着/3`
- 近战伤害 = 武器伤害 + `力量/2`（远程用感知）

### 噪音（本副本的"丧尸含量"引擎）
安静时楼层稀疏；一吵整层活过来。
阈值 **6 / 10 / 14** → 分别召唤 逐尸 / 爬行者 / 尸群(3只)。
**按回合衰减 1 点**，换房间归零。

### 敌人（8 种）
逐尸(dp3/hp6) 丧尸(dp5/hp12) 爬行者(dp4/hp8) 尸犬(dp5/hp10/先攻8)
嘶叫者(dp3/hp10/叫来同伴) 膨胀者(dp4/hp18/防5/毒) 伏尸(dp6/hp14/装死偷袭) 尸王(dp/hp34/boss)

## 九、给 AI 的三条工作纪律

1. **改完必须跑测试**，红了不许往下走
2. **排查问题先读操作日志**（`DebugLog`），不要靠截图猜 —— 本项目曾因此漏掉一个极明显的 bug
3. **截图验收时对比 sha256**：如果两张不同状态的图 sha256 相同，说明**画面根本没更新**（曾靠这个发现"角色面板导致画面冻结"的阻塞级 bug）
