# 《轮回回廊》产品蓝图与差距分析

**目标定义（用户拍板）**：做出**像《博德之门》《开拓者》那样的 CRPG**。
**版本** v0.1 · **配套** [游戏策划案](轮回回廊_游戏策划案.md) · [五界设计方案](轮回回廊_五界设计方案.md) · [战斗与美术规格](轮回回廊_战斗与美术规格.md)

---

## 零、先说一句实话：方向已经变了四次

| 时间线 | 方向 | 对代码的影响 |
|---|---|---|
| 第 1 次 | 单副本垂直切片（惊变公寓） | 已实现并跑绿 |
| 第 2 次 | 五个世界自由进入 | `hub.gd` / `scenario.gd` 需重构（数据驱动） |
| 第 3 次 | 2D 像素 + 火纹式战棋 | `iso_map.gd` / `combat_manager.gd` / `combat_scene.gd` **重写**，2 项测试作废 |
| 第 4 次 | BG / 开拓者级 CRPG | 规则层、叙事层、内容量都要**数量级提升** |

**结论**：`iso_map.gd`（等距渲染）与 `combat_manager.gd`（6 AP）已经确定要作废，但**地基还没有**。因此本蓝图的第一个建议是：**先建与最终形态无关的地基，再谈玩法细节**。

## 一、BG / 开拓者级 CRPG 的七根支柱

| # | 支柱 | BG3 / PF:WotR 的体现 | 我们现状（代码实测） | 差距 |
|---|---|---|---|---|
| 1 | **规则深度** | D&D5e / Pathfinder 1e：等级 1–20、职业与子职、法术 200+、专长 100+、状态 40+ | 9 属性 / 12 技能 / 5 天赋，**无等级、无专长树、无法术** | ★★★★★ |

### 现实预期（必须讲清楚的数字）

| 作品 | 内容量 | 团队 / 周期 |
|---|---|---|
| 博德之门 2 | ~100 小时 | 黑岛 ~50 人 / 2 年 |
| 开拓者：正义之怒 | ~80 小时 | Owlcat ~60 人 / 3 年 |
| 博德之门 3 | ~100+ 小时 | 拉瑞安 ~400 人 / 6 年 |

**我们可行的路径不是"缩小版 BG"，而是**：把**系统深度**做到 BG 级（这部分靠代码与规则书，可控），把**内容量**按章节滚动交付，每个章节都是一个完整可玩的数小时体验。

## 二、最关键的一个架构决策：逻辑与渲染解耦

三次方向调整里，唯一反复被推翻的都是**表现层**（等距→方格、色块→像素）。所以地基必须让表现层可替换：

```
              ┌──────────────── 逻辑层（与视角无关）────────────────┐
              │  网格 = 方格（Grid）· 战棋回合 · 规则引擎 · 任务/对话 │
              └───────────────────────┬──────────────────────────────┘
                                      │ 只暴露：格子坐标 / 单位 / 地形 / 事件
              ┌───────────────────────┴──────────────────────────────┐
              │  渲染层（可替换）                                    │
              │  A. 方格俯视像素渲染器（火纹观感）                    │
              │  B. 等距像素渲染器（BG / 开拓者观感）                  │
              │  C. 占位渲染器（纯色块，保证素材未就位也能跑）          │
              └──────────────────────────────────────────────────────┘
```

**收益**：视角之争不再阻塞开发。今天做方格渲染器，明天想要 BG 的等距观感，只换渲染器 + 素材，逻辑与测试**零改动**。

> 补充说明：BG1/2 与开拓者其实都是**等距渲染 + 方格/自由移动逻辑**。所以「火纹的方格」与「BG 的等距」并不冲突——冲突的只是画笔。

## 三、规则深度蓝图（有规则书蓝本，不必自创）

规则书（无限恐怖 2.5RE / RM 核心）本身就是 D&D 衍生的**骰池系统**，深度足够撑起 CRPG：

| 系统 | 规则书依据 | 落地设计 |
|---|---|---|
| **等级与 XP** | 属性 = 当前值×1XP；技能 (等级−1)×2XP、0→1 = 3XP；专长 = 等级×3XP | 引入等级 1–10（切片）/ 1–20（完整），XP 由任务/表现结算 |
| **专长树** | 建卡总 70XP、专长必投 15–45XP、每级 ≤ 关键属性 | 每级 3×等级 XP，专长分生理/心智/互动/战斗四系 |
| **技艺（法术等价物）** | D/C/B/A/S 五级技艺体系（规则书有 1000+ 页条目） | 按界裁剪：仙侠=剑诀/术法、科幻=黑客/EMP、魔幻=元素法术 |
| **模板与血统** | rmcore：血统 / 改造 / 瞳术 / 修真 / 魔导书，模板互斥 | 主神空间兑换，构成"职业"等价物，提供 build 多样性 |
| **状态效果** | 重伤、剧痛、不良状态点数与严重后果 | 流血 / 中毒 / 灼烧 / 剧痛 / 感染 / 辐射（五界各一套） |
| **装备体系** | 武器 / 护甲 / 奇物 / 消耗品 / 分级 D–S | 装备词条 + 武器耐久（火纹原生机制，废土世界直接契合） |
| **基因锁** | 五阶设计、熟练度、维持代价、失控 | 本作招牌"爆发系统"，可作职业之外的成长线 |
| **队伍** | 人造人 500 分 / 随从 200 分 / 动物伙伴 | 同伴系统的基础（含好感与专属任务） |

**目标**：让玩家在**建卡阶段就有 5–10 种可行 build**，而不是现在的 5 个天赋。

## 四、叙事引擎蓝图（BG 的灵魂在这里）

| 能力 | 现状 | 目标 |
|---|---|---|
| 对话树 | 纯 GDScript 字典，2 个 NPC | 数据驱动 + 编辑器友好（JSON/资源文件） |
| 检定选项 | 支持（D10 vs DC） | 保留，扩展「属性/技能/物品/任务/好感」多类条件 |
| 好感度 | 无 | 同伴好感 0–100，影响剧情与结局 |
| 阵营/道德 | 无 | 双轴（秩序–混乱 / 仁慈–冷酷）影响 NPC 反应与结局 |
| 任务链 | 3 个平铺任务 | 多阶段任务链 + 前置依赖 + 失败分支 + 可选解法（战斗/潜行/交涉） |
| 结局矩阵 | 3 个固定结局 | 世界结局 × 角色结局 × 同伴结局的组合 |
| 日志 / 百科 | 无 | 任务日志、线索档案、世界观百科（无限流小说的"轮回者档案"感） |
| 叙事量 | ~30 行 | 单个世界章节 **1.5–3 万字**（BG 级密度需 10 万字/章节） |

## 五、分阶段路线图（地基优先）

| 阶段 | 交付 | 与最终形态的关系 | 工作量 |
|---|---|---|---|
| **A · 地基** | 数据驱动世界注册表 · 存档 v2（含版本迁移）· **逻辑/渲染解耦的 Grid 与渲染器接口** · 数据校验测试框架 | **无论火纹还是 BG 都复用** | 5–6 人日 |
| **B · 规则引擎** | 等级/XP · 专长树 · 技艺系统 · 状态效果 · 装备词条 · build 校验 | 支柱 1 | 8–12 人日 |
| **C · 叙事引擎** | 对话系统升级（条件/好感/阵营）· 任务链 · 日志百科 · 结局矩阵 | 支柱 3、4 | 8–12 人日 |
| **D · 战斗引擎** | 战棋回合（移动/行动/反击/追击/相克/地形）· 技艺施放 · 掩体与高低差 · 战棋 UI | 支柱 2 | 8–10 人日 |
| **E · 首个完整章节** | 惊变公寓升级为「3–5 小时完整世界」：三阶段 + 支线 + 多解法 + 完整叙事 | 支柱 5 的样板 | 10–15 人日 |
| **F · 扩展与同伴** | 其余四界 · 同伴系统与好感线 · 主神空间完整化 · 像素素材铺开 | 支柱 4、5、6 | 20–30 人日/界 |

**里程碑判断**：**阶段 A–E 完成 = 一个"BG 味道的垂直切片"**（有深度、有选择、有战术），约 40–55 人日；此后每增加一界约 20–30 人日，向 BG 级内容量滚动逼近。

## 六、沉没成本控制（三条纪律）

1. **地基先行**：阶段 A 完成前，不再写任何与具体玩法强绑定的代码（尤其是地图渲染与战斗 UI）。
2. **表现层可替换**：任何渲染代码都不许进入逻辑层；素材缺失时用占位渲染器，保证测试常绿。
3. **每阶段可交付**：每个阶段结束都必须能跑通「主菜单 → 建卡 → 主神空间 → 世界 → 结算」全链路，避免半成品堆积。

## 七、风险

| 风险 | 说明 | 对策 |
|---|---|---|
| **内容量是真正的瓶颈** | 系统可以写，对话/任务/地图是海量人工 | 用 AI 批量产出草稿 + 模板化任务骨架 + 数据校验；按章节滚动交付 |
| 规则深度导致学习曲线陡峭 | 骰池 + 专长 + 技艺 + 状态，新手劝退 | 分界教学：第 1 界只用基础规则，逐界解锁新系统 |
| 方向继续漂移 | 已发生 4 次 | 阶段 A 地基让表现层可换，把漂移成本压到最低 |
| 单人 + AI 协作的产能上限 | 无美术/无配音/无 QA 团队 | 像素美术用 AI + CC0；叙事用模板 + 校验；测试全部自动化 |
| 平衡失控 | 专长 + 技艺 + 装备组合爆炸 | 建立数值校验测试（build 模拟器），关键公式集中在一处 |
| 存档兼容 | 规则与内容持续扩张 | 存档版本号 + 迁移函数，从阶段 A 就做 |
