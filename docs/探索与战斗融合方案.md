# 探索与战斗融合方案

> **⚠️ 实现状态（本文写于 10-01，已基本落地，但有三处与现况不符）**
>
> | 本文说法 | 当前实现 |
> |---|---|
> | 「探索模式（**实时**）」（§2.1） | ❌ **已改为回合制**：玩家行动一次 → 敌人各走一步。理由：只有回合制才能让"敌人什么时候转身"可观察、可计算，潜行才有策略；实时漂移玩家无法预判 |
> | 「逃跑：移动到地图边缘」（§2.3） | ⚠️ 实际是**退回上一间箱庭**（由 `tests/flee_test.tscn` 守护） |
> | 「15 项回归测试」（§6） | ⚠️ 现为 **26 项** |
>
> 其余核心主张（同一张地图不切场景、视野锥 + 巡逻、潜行先手、地形与尸体状态延续）
> **均已实现**。详见 `docs/文档状态总览.md`。

> 现状问题：`scenario.tscn`（探索）与 `combat_scene.tscn`（战斗）是**两个场景**，
> 接敌时整屏切换、战后重建地图 —— 玩家的位置、地形状态、掉落物都会被重置，
> 玩起来像"两个游戏"。本文给出几种成熟做法与推荐方案。

---

## 一、五种主流做法

| 游戏 | 做法 | 融合度 | 关键机制 |
|---|---|---|---|
| **博德之门 3** | **同一张地图**，实时探索 ↔ 回合制战斗（只是"时间模式"变了） | ★★★★★ | 战斗不切场景；可**预布置**（潜行、摆油桶、抢高地），这些在开战后直接生效 |
| **神界：原罪 2** | 同上（BG3 的前身） | ★★★★★ | 地形元素（油/水/火）跨模式持续，战斗结束地表状态还留着 |
| **XCOM 2** | 一张战术地图，**隐蔽状态**自由移动，被发现即进入回合制 | ★★★★ | 「隐蔽 / 被发现」是本作最核心的节奏设计 |
| **战场女武神** | 指挥视角（全局）↔ 选中单位进入**实时单兵行动**（BLiTZ） | ★★★★ | 探索与战斗是同一次连续操作，从不切场景 |
| **暗黑地牢** | 走廊里实时推进 + 遭遇时**同屏**切回合制（画面不换） | ★★★ | 战斗结束直接继续走 |
| *火焰纹章：风花雪月* | 据点自由探索 + **独立战场**（切场景） | ★★ | 与我们现状类似 —— 也是被抱怨割裂的那种 |

**结论**：主流趋势是 **「一张地图 + 状态机切换」**，而不是「两个场景来回跳」。

## 二、推荐方案：BG3 骨架 + XCOM 节奏

### 2.1 核心结构

```
一张地图（惊变公寓一层，像素方格）
│
├─ 探索模式（**回合制**）
│    · 点击移动（不耗 AP）；**你动一次，敌人才动一次**
│    · 换房间时噪音重置（你是新来的）
│    · 调查、拾取、对话
│    · 敌人有「视野锥 + 巡逻」
│    · 可潜行（未被发现 = 隐蔽状态）
│
└─ 战斗模式（回合制，同一画面）
     · 敌人索敌 / 玩家先攻
     · AP 制指令菜单（已实现）
     · 血统技能 / 排斥 / 失控（已实现）
     · 战斗结束 → 回到探索模式
```

**接敌判定**（三种，都进入战斗）：
1. 玩家走进敌人视野 → 战斗（敌人先手）
2. 玩家在敌人背后**未被发现**时攻击 → 战斗（**玩家先手：敌方首回合不行动**）
3. 剧情触发（开门、拾取关键道具）

### 2.2 为什么不切场景很重要

| 保留的东西 | 玩家能做的事 |
|---|---|
| **角色位置** | 潜行接近、绕后、抢高地后再开战 |
| **地形状态** | 提前打碎掩体、点燃油区，战斗里直接生效 |
| **掉落与尸体** | 战利品**掉在地上**，不用"结算面板" |
| **敌人状态** | 打残的敌人不会因为你离开就回满血 |
| **血脉状态** | 排斥度、失控风险跨模式连续（失控在探索里也会触发） |

### 2.3 战斗内可做的事（因为地图没变）

- **逃跑**：移动到地图边缘 → 退出战斗，敌人**追击**（进入探索后仍在追）
- **增援**：枪声/爆炸会吸引地图上其他敌人靠近（`枪声会引来更多东西` 这句物品描述终于有意义了）
- **多波遭遇**：走廊里打完一波，转角又遇一波，节奏连贯

## 三、对我们系统的额外收益

| 已有系统 | 融合后的新价值 |
|---|---|
| **血统 / 排斥** | 失控不再只发生在战斗里 —— 探索中也可能因血脉暴走打伤 NPC 或暴露位置 |
| **RE2 箱庭地图** | 环形动线原本为"绕圈"设计，现在真的能用来**绕后偷袭** |
| **地形（高地/掩体/危险区）** | 探索时就能"布阵"，而不是开战后再挪 |
| **单人队伍（现状）** | 未来加队友后，可在探索中分头包抄 |
| **指令菜单** | 探索模式不做菜单（点击即走），战斗模式才弹 —— 两种手感自然区分 |

## 四、技术落地路径

把 `combat_scene.gd` 的职责抽成一个**可挂载的战斗控制器**，由探索场景持有：

```
scenarios/r001_apartment/scenario.tscn        ← 唯一场景
├─ GridWorld + PixelGridRenderer              ← 两种模式共用（已有）
├─ scenario.gd（探索控制器）
│    · 点击移动 / 交互 / 调查 / 对话
│    · 敌人视野与巡逻
│    · 检测接敌 → battle.begin(...)
└─ battle_controller.gd（战斗控制器，新）
     · 从 combat_scene.gd 抽出：AP 制、先攻、指令菜单、血统技能、战斗特写
     · battle.begin(encounter) / battle.end()
     · 战斗期间禁用探索输入
```

| 阶段 | 内容 | 影响面 |
|---|---|---|
| **F1** | 抽出 `battle_controller.gd`（纯搬运，行为不变） | 中（需完整回归） |
| **F2** | `scenario` 接入：接敌时启用战斗控制器，不再切场景 | 中高 |
| **F3** | 敌人「视野锥 + 巡逻」与**潜行先手**（未被发现时开战 → 敌方首回合跳过） | 中 |
| **F4** | 逃跑 / 追击 / 增援 / 战利品落地 | 中 |
| **F5** | 删除 `combat_scene.tscn` 与 `demo_scene.gd`（两套旧战斗逻辑一并退休） | 低 |

> **兼容性**：`CombatManager`（回合/AP/AI/结算）与 `BattleAnim` 完全复用，不改；
> `battle_controller.gd` 只是把"场景壳"换成"组件"，回归测试可继续沿用。

## 五、取舍与风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 改造面大 | `combat_scene.gd` 911 行 + `scenario.gd` 701 行都要动 | 先做 F1 纯搬运，让行为不变；每步跑全套回归 |
| 探索输入与战斗输入冲突 | 同一份 `_unhandled_input` 要分模式处理 | 用明确的 `mode` 状态机 + 单测覆盖 |
| 视野/巡逻是全新系统 | 没有现成代码 | F3 单独排期，先做静态视野锥 |
| 存档结构变化 | 战斗状态若跨场景保存会复杂 | 融合后**不再需要** `pending_combat` / `explore_state` 那套跨场景传递，反而简化 |

---

## 六、验收标准

1. 接敌时**画面不切换**，玩家的位置、地形、掉落物全部保留。
2. 战斗结束立即回到自由移动，**所见即所得**（尸体和战利品就在原地）。
3. 未被发现时开战 → 敌方**首回合不行动**（潜行突袭的收益可见）。
4. 战斗中可逃跑，且敌人会在探索模式继续追击。
5. `pending_combat` / `explore_state` 这套跨场景状态传递被彻底删除（融合的副作用是**代码更简单**）。
6. 全部回归测试保持全绿（当前 **26 项**）。
