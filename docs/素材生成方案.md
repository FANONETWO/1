# 《轮回回廊》素材生成方案（AI 像素美术）

> **⚠️ 实现状态：AI 生图路线已基本弃用，本文主要作为「流程纪律」参考**
>
> | 本文主张 | 现况 |
> |---|---|
> | 用 **Leonardo REST API** 批量生成 | ❌ 额度不可用，未走通 |
> | AI 生成 **16×16 tile** | ❌ **实测模型在这个尺寸只会产出噪点**（墙与地板分不清）。已改为 **`tools/pixelart/gen_tiles.py` 程序化生成** |
> | AI 生成装饰物（血迹/纸箱） | ❌ 免费额度耗尽（Pollinations 返回 402）。已改为 **`tools/pixelart/gen_deco.py`** |

> | 「可审批、可复现、可追溯」的流程纪律 | ✅ **仍然成立**，现由 `gen_tiles.py` / `gen_deco.py` 落实（固定种子、可复跑） |
>
> **结论：tile 与装饰这类「规则几何 + 有限调色板」的东西，程序化比 AI 更可控。**

**版本** v0.1 · **配套** [战斗与美术规格](轮回回廊_战斗与美术规格.md) · [产品蓝图](轮回回廊_产品蓝图与差距分析.md)

## 一、生成方式与硬限制（必须先明确）

| 路线 | 做法 | 成本 | 谁能做 |
|---|---|---|---|
| **A · API 全自动（推荐）** | 你创建 API Key → 我写脚本调 Leonardo REST API：提交 → 轮询 → 下载 → 后处理 → 入库 | API 独立按量付费；新账户有**少量起始免费额度**，之后需充值 | 我（需 Key） |
| **B · 网页生成 + 我接入** | 你用网页免费额度按本文档生成 → 图片丢进 `assets/raw/` → 我后处理与接入 | 免费（非商用） | 你（生成）+ 我（处理） |

**硬限制（诚实说明）**：我没有浏览器自动化工具，无法登录网站点击生成；Leonardo 网页免费额度**不等于** API 额度，API 需单独创建 Key（[API 指南](https://apiframe.ai/guides/leonardo-ai-api-guide)）。

**Key 安全**：Key 只写入 `D:\1\infinite_loop\.env.local`（已加入 `.gitignore`），绝不提交、绝不写进任何 `.gd` 或文档。

## 六、后处理流水线（概念图 → 真像素）

```
assets/raw/<batch>/原图.png
   │  1) 裁剪主体（去多余留白）
   │  2) 最近邻缩放到目标尺寸（16×16 / 16×24 / 32×32）——禁止双线性
   │  3) 量化调色板（每界 16 色盘 / 单图 ≤24 色）
   │  4) 去背景为透明（阈值 + 手动修补）
   │  5) 网格对齐（脚底/中心对齐）
   ▼
assets/tiles|sprites/<world>/<name>.png  +  素材登记
```

我负责用捆绑的 Pillow 脚本完成 1–5 步（批量、可复跑）；生成端（Leonardo）产出的原图一律进 `assets/raw/`，**不直接使用**。

## 七、命名与接入规范

```
assets/
  raw/<batch>/            原始生成图（不参与打包）
  tiles/<world>/*.png     16×16 地形
  sprites/<world>/*.png   16×24 单位（idle/walk/attack/hit）
  sprites/<world>/boss_*.png
  icons/*.png             16×16 图标
  portraits/*.png         48×48 头像
  ui/*.png                九宫格面板与选中框
  CREDITS.md              素材来源登记
```

**接入方式**：渲染层实现 `PixelGridRenderer extends GridRenderer`，从上述路径加载图集；逻辑层（`GridWorld`）零改动——这正是前一步做「逻辑与渲染解耦」的原因。
